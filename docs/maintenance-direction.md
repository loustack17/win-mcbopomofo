# 維護與架構方向

這個 fork 會持續維護，也會逐步整理過去留下的程式碼與工具。目標是讓專案更容易理解、建置與修改，減少重複的流程及需要維護的語言種類。

## 語言選擇

以 C++ 為主要實作語言，優先用現有技術把架構整理好。希望自行維護的實作能集中在一種語言；有明確需要時，最多使用兩種。

Rust 或 Zig 可以作為第二種語言的選項，但要先確認它能取代哪些既有部分，以及是否真的減少維護負擔。不是為了換語言而重寫，也不以同時引入 C++、Rust、Zig 三種語言為目標。

自行維護的 C、VBScript 與 PowerShell 會逐步減少。仍有必要的 Windows 建置、安裝與系統整合工具，在替代方案完成並驗證之前保留。第三方相依套件的語言與原始內容不必為了這個方向而改寫。

## 整理順序

1. 先查清楚呼叫關係，移除確認沒有使用的檔案、舊流程與重複實作。
2. 合併重複的建置、安裝及程序管理工作，讓每件事有清楚的負責位置。
3. 評估仍在使用的 C、VBScript 與 PowerShell；能刪除就刪除，需要替代時再選擇合適的實作。
4. 若 C++ 已能清楚處理，就沿用 C++。只有具體的替代需求才評估 Rust 或 Zig，並一個模組、一個流程地遷移。

## 驗收方式

每次整理都要能說清楚減少了哪些重複工作、相依性或維護成本，並確認輸入行為、選字視窗、建置、安裝及升級沒有退步。替代方案通過相關驗證後，才移除舊實作。

GitHub 的語言比例只作為參考，不是整理成果的驗收標準。不透過隱藏檔案或調整統計分類，讓比例看起來更單純。

這份文件記錄後續方向，不代表目前已決定重寫或全面遷移。現有架構的說明見[系統架構](system-architecture.md)。
